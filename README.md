# سینه‌ورس (CineVerse)

پلتفرم پخش آنلاین فیلم و سریال با رابط فارسی و راست‌به‌چپ: کتابخانه فیلم و سریال،
اشتراک و محتوای ویژه، پنل مدیریت محتوا و تنظیمات سایت.

## معماری

| بخش | فناوری | مسیر |
|-----|--------|------|
| رابط کاربری | React 18 + Vite + React Router، CSS ماژول‌به‌ماژول | `frontend/` |
| API | Node.js (ESM) + Express + Zod | `backend/src` |
| پایگاه داده | PostgreSQL 16 | `backend/migrations` |

رابط کاربری همه درخواست‌ها را به مسیر هم‌مبدأ `/api/v1/...` می‌فرستد؛ در حالت
توسعه، سرور Vite این درخواست‌ها را به سرویس API پروکسی می‌کند، بنابراین
کوکی‌های نشست بدون نیاز به CORS کار می‌کنند.

## اجرای محیط توسعه

نیازمندی: Docker و Docker Compose.

```bash
docker compose -f docker-compose.base44.yml up -d --build
```

این فرمان پایگاه داده را بالا می‌آورد، وابستگی‌ها را نصب می‌کند، مهاجرت‌ها و
داده‌های نمونه را اجرا می‌کند و سپس API و رابط کاربری را با بارگذاری خودکار
(live reload) اجرا می‌کند. برنامه روی <http://localhost:3000> در دسترس است.

> داده‌های نمونه فقط برای توسعه هستند: عنوان‌ها، سال‌ها و امتیازها اطلاعات
> عمومی واقعی‌اند اما پوسترها تصاویر جایگزین و آدرس‌های پخش، ویدیوهای نمونه
> عمومی هستند؛ هیچ فیلم دارای مجوزی در مخزن نیست.

### حساب‌های نمونه

| ایمیل | رمز عبور | نقش |
|-------|----------|-----|
| `admin@cineverse.local` | `CineVerse!2024` | مدیر اصلی |
| `support@cineverse.local` | `CineVerse!2024` | پشتیبان (دسترسی محدود) |
| `user@cineverse.local` | `CineVerse!2024` | کاربر با اشتراک فعال |

رمز عبور با متغیرهای `SEED_ADMIN_PASSWORD` و `SEED_USER_PASSWORD` قابل تغییر است.

### متغیرهای محیطی

* مقادیر پیش‌فرض غیرحساس توسعه در `backend/.env.base44-defaults` قرار دارند.
* کلیدهای واقعی (مثل `JWT_SECRET`) از فایل بیرون مخزن `/run/base44/app.env`
  خوانده می‌شوند و در `backend/.env.example` فهرست شده‌اند.
* برای توسعه محلی روی HTTP، مقدار `COOKIE_SECURE=0` را تنظیم کنید.

### اجرای محلی بدون Docker (اختیاری)

```bash
cd backend && npm install && node src/db/migrate.js && node src/db/seed.js && npm run dev
cd frontend && npm install && npm run dev
```

## کنترل دسترسی

* نقش‌ها: `user`، `support` و `admin`. هر مسیر مدیریتی در سمت سرور بررسی
  می‌شود (`requireAdmin`) و کارهای مخرب مثل حذف محتوا، تغییر نقش کاربران و
  ذخیره تنظیمات فقط برای `admin` مجاز است (`requireStrictAdmin`).
* آدرس‌های پخش از سمت سرور و پس از بررسی اشتراک صادر می‌شوند؛ فایل اصلی هرگز
  به‌صورت مستقیم برای کاربران بدون دسترسی ارسال نمی‌شود.
* پنهان کردن دکمه‌ها در رابط کاربری جایگزین کنترل دسترسی نیست.

## وضعیت استقرار

این مخزن هیچ پیکربندی استقرار (Dockerfile تولیدی، CI یا پلتفرم میزبانی) ندارد؛
`docker-compose.base44.yml` فقط برای محیط توسعه است و نباید به‌عنوان استقرار
تولیدی استفاده شود. برای انتشار نسخه تولیدی باید مقصد میزبانی مشخص شود؛ سپس
ساخت تولیدی رابط کاربری (`npm run build`)، اجرای API با `NODE_ENV=production`
و پایگاه داده مدیریت‌شده به‌همراه مقادیر واقعی متغیرهای محیطی پیکربندی می‌شوند.
پرداخت واقعی و پخش از سرویس ابری نیز در این نسخه پیکربندی نشده است.
